# G：原生 ABI 核实、恢复碰撞与可见目标拾取

## 与 F 的不同

F 的测试与错误的 C++ 原型一致，无法验证真实引擎调用。G 首先读取实际 SkyrimSE.exe，不把 CommonLib 声明当作 ABI 真值。

当前 1.5.97 EXE SHA256：5666e1bddd01bcab31ecf11691ef1a3f22e1541af79f2bc0e55318533cfe5d12。

独立证据：

- 调用方 RVA B27573：`lea rdx,[rsp+40h]`，结果缓冲地址；R8/R9分别准备两个碰撞体。
- B27592：虚表slot1调用；B27595：`cmp byte ptr [rax],0`，消费的是指针而不是布尔寄存器值。
- 被调函数 DD6786 保存 R8，DD6789 保存 RDX；DD678C 从 `[r9+2Ch]`读取第二碰撞体过滤信息；DD679C 写入 `[rbx]` 结果；DD679E 令 RAX=RBX返回缓冲指针。
- 本地 SexLabpp CollisionHandler.cpp:247—249 的四参数原生钩子与本体指令一致；它是调用链参考，不将崩溃归咎于该Mod。

因此生产钩子使用 `bool*(this, bool* result, const collidable* A, const collidable* B)`。先完整转发四参数至原钩子，保留它返回的指针及否决结果；仅当前玩家/坐骑组对改为false。非骑乘时不读取额外碰撞组。下骑与Revert清除组对，不改变原生存档格式。

## 不再自证的验证

1. `tests/verify-native-abi.cjs` 从安装目录EXE解析PE段，核验上述实际机器码字节，未知版本直接失败。
2. `tests/collision-abi.asm` 是独立MASM调用/返回边界，不包含C++钩子类型声明；直接设置RCX/RDX/R8/R9调用生产Check，汇编原函数记录四个实际参数并写入/返回结果缓冲。
3. ABI桥覆盖10000次有/无骑乘组、四参数身份、返回指针身份、缓冲区前后保护字节；逻辑回归另测原钩子false/替代结果地址、原生地面/其他角色、重建与清除。旧三参数签名不再能通过类型检查或此调用边界。
4. 检视实际Release plugin.obj中Check反汇编：原函数调用前保留R8/R9，RCX/RDX未被改写；返回指针保存至RBX，拒绝时写 `[rbx]`，返回RAX=RBX。不是只检查测试替身生成的代码。

## 原用户故障

恢复F中因整体回退而停用的窄范围可见骨骼拾取、遮挡深度转存及原生碰撞组对过滤；不更改DoM、五人组骨架或Serana。DoM日志已证明输入到达但目标为空；无碰撞体的可见目标现在有不依赖物理体的入口。五人组异常日志提示控制器接触/无输入速度，而非未生成爬行动画；组对过滤针对这一缺口，但没有在本轮引擎内证明它消除了全部抖动。

测试与部署不能被表述为游戏验收。真实Havok接触缓存、第三方钩子最终顺序及DoM目标运行状态仍需游戏日志证实。日志G标记区别已撤回F；保留过滤命中计数与目标诊断。
