# 0.3.1 状态与存档自检（2026-10-15）

范围：C固定、D临时敌对抑制、E/F牵引、B完整还原及其跨存档/异步边界。未扩展玩法；保留现有ESP、INI、模型和动作。本轮仅计划替换DLL。

## 确认并修复

1. E检查与创建原来共用Applying并一律保存。现在分开Checking/Applying：尚未创建的Checking不记入TETH，避免保存预检查时读档误认目标已有的绳索。已保存牵引先Reconciling，通过GetLeashHolder确认玩家是持绳人后才开放运动；无绳或其他持绳人清掉本地记录。TETH v1布局不变，兼容旧记录，但旧0.3.0记录没有预检查阶段信息，无法从旧数据完全还原当时的所有权。
2. 原解除派发失败每次B重试均可再调用并弹提示，且持续等待；状态查询每秒可重复入队。现在查询单次在途，派发失败至少间隔1秒、最多3次；请求10秒未返回进入Failed，停止自动调用，不循环刷提示。只读查询超时可作废旧token，F允许重新确认；已接受的创建/断开不重复派发，避免迟到操作删掉后来新建的绳索。
3. Failed不再阻挡B还原本插件的坐骑/scale/速度/AI/标志。仍保留未确认绳索的清理记录，不伪装为已经断开，并阻止同目标重建/骑乘。迟到的有效创建回调会立即进入清理；迟到的断开回调可完成清理。若框架/VM始终不回调，不能强称绳模型已删除；应恢复框架后通过F或正常读档重新确认，卸载前确认清理完成。这是可报告的外部接口故障，不是后台无限重试。
4. 解除事件增加会话与事件序号边界，旧存档或同存档旧绳的排队通知不能清掉较晚的新状态；所有A～F排队施法任务也捕获会话，读档后不再执行旧施法。布尔返回类型无效不再被误判为“断开完成”。
5. C跨cell修正加入同线程重入保护，避免MoveTo触发Actor更新再进入MoveTo。NPC更新只校正同cell坐标/角度；跨cell补救由主循环最多每秒一次，失败时不把原cell坐标写入错误cell。普通MoveTo/SetPosition仍即时拦截。绑定中的NPC后来进入scene不再触发旧坐骑自动还原而意外解锁；死亡与显式B仍解除。
6. 固定cell解析失败时保留原状态并标记待释放，而不是丢记录导致遗留限制。对象随后加载时恢复C/D绑定或执行待释放，死亡目标只清理不复活。D临时抑制撤回后使用原生实时敌对关系，不强制敌对，也不永久改阵营。
7. B原来只在当前life为restrained时写回原life；E会临时把原本restrained的NPC置Alive，直接B可能漏恢复。现在Alive/Restrained两种受控状态都能恢复保存的原状态，不覆盖死亡。B还原中拒绝新绑定/牵引与骑乘，避免半还原状态被再次接管。

## 边界

C只接受坐骑；D只接受当前敌对人形；E只接受未绑定/骑乘/牵引的坐骑；F只处理本插件记录；B也支持D非坐骑。C/D/E互斥；保存读档发现冲突绑定或已非坐骑时，牵引走清理而非开放移动。敌人重返敌对取决于原生关系及其他Mod后续改变，不强制重启战斗。

LeashFramework接口没有暴露独立绳实例ID。本插件的事前检查、持绳人确认和事件边界不能证明与第三方同时替换同一玩家—NPC绳索完全无竞争；不修改框架源码，也不声称覆盖绕过引擎入口的任意传送。原手部装备仍按基础物品恢复，不区分不同附魔实例。
