## 已发现并处理的离线问题

1. 原版骑手片段 98 轨、索引从 1 起，不能当作完整 99 轨直接替换；已按绑定补齐。
2. 骑手跳跃不能仅套无事件的静态姿势；保留原人形跳跃片段的注释和时间。
3. 加法动作层不能再次应用绝对全身姿势；使用中性 additive 片段。
4. 引用删除需要清理状态，避免动态 FormID 后续复用误匹配。
5. 暂停菜单时仍须保留视觉附着，不能撤销偏移后直接返回。
6. 下骑不使用未知参数的 TryMoveTo 调用，改为明确的落地及通路射线探测。
7. 只还原本插件接管的标志位，不覆盖其他 Actor 状态。

## 仍不能标为完成的内容

1. B空中/安全落点不足时原来会直接return，丢失请求。现记住待还原状态，间隔0.25秒重试且不重复HUD提示；无目标B对暂未加载引用也保留请求。co-save版本4持久化该状态，兼容版本1—3；加载/对象重载优先还原，不重新强制趴下。
2. 下骑与B显式发送SprintStop和moveStop；玩家退出骑手标记后重置默认动作。B先移除目标标记并停止动作，再归还原生命状态/标志/AI；不会对已死亡目标写回alive，不对原AI关闭目标强制评估包。
3. 速度来源改为玩家物理控制器水平速度，按Havok世界比例换算；不以更新时序敏感的单帧位置差决定动作。增加步态退出阈值，避免临界速度来回切换；转向使用弧度/秒，避免30/60/144FPS产生不同动作。
4. 暂停不切动作，不对未变化的位置/朝向反复写入。继续禁止所有运行时骨骼节点偏移及额外场景图更新；未修改ENB/TAA，不能据此保证当前整合的全部拖影已消除。
5. 实际Restore/RestoreAll/Save/Load函数体在引擎测试替身上通过：原标志/AI/生命状态、死亡保护、空中延后、未加载引用、版本1—4迁移及版本4保存/读回、截断拒绝。实际Motion.h通过20000次阈值波动、倒退及30/60/144FPS转向测试。HoldPose的20000次幂等检查、既有18段HKX身份及四足/运动/骑手相机数据检查通过。均不是游戏运行验收。

## 0.1.4 同步修正及诊断

1. 撤回0.1.2/0.1.3的SetPosition(false)与NoSim组合：保留模拟，只禁用角色间碰撞；使用SetPosition(true)同时更新引用和物理控制器，避免仅引用移动后被旧控制器位置覆盖。进入骑乘时即使引用位置相同也强制同步一次。
2. 链式挂接目标NPC的Character::Update，原更新后再同步，覆盖NPC自身更新晚于玩家更新的顺序；不修改骨骼节点。不重置任何其他NPC的位置，目标位置/角度未变时不重复写入。
3. 日志新增Player更新钩子首次到达；每次骑乘最多8条、间隔0.5秒记录更新次数、双方位置、模型根位置、NPC更新后的同步误差、物理速度及期望/实际动作派系等级。若仍异常，需依据这些实际数据区分更新未执行、物理回写、模型未更新或OAR条件问题，不宣称已确定全部根因。
4. 新增实际SyncMount/RestoreController函数体的双位置模型回归：复现只移动引用后被代理拉回；新代码跨2500次模拟更新保持引用/代理一致，验证静止不重复写入、旧代理强制同步、原控制器标志归还。B还原、AI、动作阈值及既有动画检查仍通过。模型测试不等于引擎实测。

## 0.1.5 实现逻辑审查

1. 检查Convert/HoldPose、Mount、PlayerUpdate/NPCUpdate/SyncMount、Tick动作选择、Dismount/Restore、对象加载及co-save恢复的调用顺序。此前只复核文件和已有模拟测试，不构成完整实现审查。
2. 确认动作切换先NotifyAnimationGraph后AddToFaction；事件处理有机会观察到旧OAR条件。提取SetMotion，先发布新派系等级和内部状态，再发送移动/冲刺事件；下骑同样先恢复idle等级再StopMotion。不在每帧重复发送相同动作事件。实际函数回归验证事件观察到新rank、冲刺到起跳、恢复移动与静止。
3. 确认Tick因死亡/剧情调用Restore时，Restore仍调用普通Dismount，空中或无安全落点会推迟释放。此类自动退出改走紧急下骑；普通B仍保留落地和安全落点检查及延后请求。实际Restore测试新增死亡/剧情且普通下骑不允许时的释放断言；原还原及co-save测试保持通过。
4. 同步审查：PlayerUpdate和目标NPC Update之后都调用SyncMount，只同步当前ridden对象；无运行时骨骼写入。该调用顺序仍不能证明引擎在渲染前发布模型根位置。SyncMount双位置测试中的EngineUpdate是人为测试替身，不能用其结果证明此前真实引擎必然发生控制器回写。
5. 动画审查：动作rank来自玩家控制器速度，NPC自己的速度每次同步被清零，同时处于restrained/movementBlocked。OAR能否在当前行为图中持续播放，以及实际播放速度是否受原行为图影响，尚无运行证据。HKX含有运动不等于行为图会播放；本轮不凭猜测再改生命状态、骨架或全局动画速度。
6. 还原审查：原AI/生命状态/接管位及pending保存在co-save；骑乘关系及临时控制器标志快照只在内存，读档不恢复骑乘。临时物理标志是否会被游戏存档保留、退出恢复是否影响镜头，尚需引擎实测。当前仅确认代码恢复路径与测试替身行为，不能标记完整方案验收。
7. 0.1.5只部署DLL，完整备份为MO2/backups/NPCMounts-0.1.5-logic-20261014。未修改NPC外貌、动画资产、ESP、MO2启用顺序或目录名；仍待游戏验证。
